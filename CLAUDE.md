# Кейс 3 TechArena 2026: сервисные зоны

Отвечай по-русски, коротко.

## Задача
Выбрать офисы, назначить им сайты (можно не брать) и рабочих. Max:
`Σreward − Σdistance[o][s] − Σcost(открытых) − α·(max задач − min задач)`.
Строго: `|sites| ≤ maxSize`; число сайтов открытых офисов различается ≤ `maxDifference`; каждая задача сайта —
навык рабочего своего офиса; ни одна точка (сайт или офис, даже неназначенный/закрытый) не в двух оболочках
(оболочка = сайты + офис). Лимит 300 с/тест, **решатель работает 280 с**, ядра все. Только `instance.json` →
`solution.json`, сети нет. Подробно — `SOLVER.md`.

## Экономь контекст
- Не открывай: `task/instance*/instance.json`, `task/Techarena.pdf`, `task/samples/`, `archive/`, `results/*.json`.
  Нужен факт об инстансе — посчитай скриптом, выведи только число. `grep -r` — всегда с `--exclude-dir=task`
  (инстанс — одна строка JSON на сотни КБ).
- `solver/solve.cpp` (~2600 строк) не читай целиком: `grep -n '// =====' solver/solve.cpp` даёт оглавление,
  дальше читай нужный раздел или функцию по номерам строк.
- `SOLVER.md` — только когда нужна схема или оценки; `EXPERIMENTS.md` — перед правкой решателя.
- Длинные прогоны не запускай ради проверки, в PR их делает CI. Вывод команд обрезай (`| tail`).

## Команды
- `python3 bench.py 30` — сборка с флагами из `submission/cpp/Makefile`, все инстансы параллельно, валидатор, таблица.
  `--runs 3` (зёрна, медиана/макс), `--base origin/main` (A/B), `--synth` (синтетика + граничные случаи),
  `--only 1,4`, `--record` (обновить `results/best*`). Код выхода 1 при INVALID или перелёте лимита.
- Решатель: `./solve in.json out.json SEC`; env `NT` потоки, `SEED`, `DBG=1`, `FORCE_OPS=0,3`.
- Валидатор: `.venv/bin/python task/validate_solution.py in.json out.json`.
- Диагностика: `tools/bound.py` (верхняя оценка), `tools/why.py in sol` (почему сайт не взят), `tools/gen.py` (синтетика).
- Посылка: `/submit` (скилл) или `./submission/make_zips.sh` → `dist/case03_cpp.zip`.

## Закрытые тесты
Балл — на закрытых тестах, нормировка к лучшему по каждому; провал (TLE, RE, невалид) на одном тесте дороже
пары процентов на всех.
- Никаких констант и веток под открытые инстансы: параметры — из данных (масштаб, α, A, maxSize, навыки).
- Ждать: до 10⁴ сайтов и 20+ офисов, многопрофильные рабочие, навыки без рабочих, α = 0 или огромный, A = 0 или ≥ N,
  maxSize = 0, совпадающие/коллинеарные точки, координаты в [0,1] при расстояниях до 10⁵, дороги против геометрии.
- Все циклы с дедлайном; O(N²) по сайтам на 10⁴ — риск. Перед PR в решатель: `bench.py --synth 10` — всё VALID.
- Портфель стратегий страхует от плохого попадания одной стратегии.

## Правила работы
- Ветка `claude/<имя человека>-<задача>` → PR в `main`; в `main` не пушить. Люди — `<имя>/<задача>`.
- Над решателем работают трое: правь свою часть; новая стратегия — отдельной функцией за флагом (env).
- Эксперимент: `bench.py 30 --runs 3 --base origin/main` → строка в **конец** `EXPERIMENTS.md` (`/experiment`).
  Разброс между прогонами 1–2%: одно зерно ничего не доказывает. Отброшенные идеи не повторять без новой причины.
- CI на PR: A/B против `main` + синтетика, таблица в комментарии. Регрессии по инстансам не допускать.
- `results/best*` меняй только отдельным PR с `--record`; локальные решения — в `results/local/` (не в git).
