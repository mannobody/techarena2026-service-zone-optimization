# Семь решателей, 30 тестов, TL250

Подготовлен профиль `tools/benchmark_compare.py`. Он использует проверенный замороженный runner из существующего каталога, не меняя `tools/benchmark_all.py`, старые исследования или их результаты.

Запуск **из любой директории**:

```bash
./.venv/bin/python -u \
  ./tools/benchmark_compare.py run
```

По умолчанию: **TL250, NT=2, пять параллельных запусков, seed 1,2,3**. CPU-пары: `[20,21]`, `[18,19]`, `[16,17]`, `[14,15]`, `[12,13]`. Если предыдущий бенчмарк ещё работает на этих CPU, сначала остановить его через Ctrl+C.

**630 запусков; бюджет при использовании всего TL — 8 ч 45 мин**, плюс сборка семи версий, валидация и обслуживание процессов. Некоторые тесты могут завершаться раньше; обещания уложиться в восемь часов нет. Чтобы ограничить одну сессию, добавить `--hours 8`: начатые задачи завершатся, новые после лимита не начнутся. Оставшиеся задачи можно выполнить позднее повторением команды. Также доступны `--max-runs N`, `--retry-failed`.

**Ctrl+C → повтор той же команды**: готовые результаты пропускаются, прерванные задачи запускаются заново с полным TL. Кэш и сохранение результатов наследуются от основного runner.

Статус (из любой директории):

```bash
./.venv/bin/python \
  ./tools/benchmark_compare.py status
```

`plan` вместо `run` только показывает профиль и не запускает решатели. Результаты: `results/local/compare7_30_tl250_j5/`, файлы `summary.csv`, `results.json`, `progress.json`, `runs/`. Полный формат — [benchmark-all-ru.md](benchmark-all-ru.md).

## Версии

1. `v4_exact` — точная серверная v4.
2. `v8` — серверная v8.
3. `exact_neighborhoods` — последний экспериментальный кандидат.
4. `current_snapshot` — модульный `solver/`, замороженный при создании исходного каталога всех решателей. Изменения после того снимка сюда не подмешиваются.
5. `v6_hybrid` — геометрическая доработка и совместная DP по counts/load.
6. `geometry_robust` — версия с точной геометрией.
7. `v5_2_regions_safe` — безопасная региональная MILP-версия v5.2.

У v5.2 явно заданы `MIP=1`, `REGION=1` и `LD_LIBRARY_PATH` к копии HiGHS внутри нового каталога. Проверены все символы C API, используемые её loader, и 32-битный HighsInt. HiGHS 1.15.1 скопирована из существующих offline-зависимостей; сети и установки пакетов нет. Хеш библиотеки проверяется перед запуском. Это подтверждает доступность библиотеки; фактические вызовы моделей на конкретном тесте видны в stderr по `v52_mip` и `v5_mip`. Отсутствие этих строк на тесте не подменяется заявлением об улучшении MILP.

## Выбор 30 тестов

Использован существующий замороженный каталог из 657 уникальных входов. Квоты:

| Размер | Тестов |
|---|---:|
| меньше 30 сайтов | 4 |
| 30–299 | 9 |
| 300–1499 | 10 |
| 1500–4999 | 4 |
| от 5000 | 3 |

Обязательные: все пять опубликованных задач; четыре контрпримера на пересечения оболочек, закрытые офисы, распределение работников и совместное открытие офиса; известные anti и multi_deficit для анализа структурных барьеров.

Остальные выбираются методом наибольшего расстояния по признакам входов: размеры, tasks/skills, дефицит навыков, многопрофильные работники, баланс, ёмкости, цена офисов, совпадения координат, вытянутость, масштабы и различие дорожных/евклидовых расстояний. После этого разрешены замены внутри размерной категории для выравнивания CPU-очередей; обязательные тесты сохраняются. Баллы, прежние победители и ответы решателей при выборе не читаются. Это диагностическая regression/development серия с известными контрпримерами, а не новый независимый holdout.

`selection.json` сохраняет все 30 ID, исходные имена, признаки и причины выбора. Названия признаков — в `PROFILE.json`. В финальном профиле по 18 блоков «тест × seed» на слот: каждый слот содержит 126 запусков семи версий. Полный состав и хеши — в `manifest.json`, `catalog_cases.csv`, `catalog_variants.csv`.

Снимки ответов сохраняются на **60,120,150,200,240 секунде**, плюс финальный ответ. Это даст измерение позднего прироста после 150 секунд в рамках TL250. Запуск с самостоятельным TL150 изменяет расписание фаз, поэтому напрямую ему не эквивалентен.

## Другие настройки

Для другого TL, набора seeds или числа слотов нужен новый каталог:

```bash
# Два seed: 420 запусков, 5 ч 50 мин чистого бюджета при идеальном балансе.
./.venv/bin/python -u \
  ./tools/benchmark_compare.py run \
  --seeds 1,2 --out ./results/local/compare7_30_tl250_j5_s2
```

Кэш TL280 и новых TL250 не смешивается. Старые результаты сохраняются. Замороженные источники, validator и runner берутся из `results/local/all_solvers_tl280`; этот каталог нужен для создания нового профиля. Уже подготовленный профиль самодостаточен для последующих запусков: внутри находятся его исходники, входы, библиотека и runner. Для запуска оболочки по-прежнему нужен её проектный `tools/benchmark_all.py`.

Короткие тесты профиля, без запусков оптимизаторов:

```bash
.venv/bin/python tools/test_benchmark_compare.py -v
```
