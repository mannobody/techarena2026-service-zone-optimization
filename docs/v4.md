# Service Zone Optimization v4

Эта версия переносит ранее подготовленную серверную сборку v4 в основной модульный
решатель `solver/`. Генетический поиск наборов офисов и ограниченный поиск назначения
многопрофильных работников дополнены переиспользованием буферов, точной геометрией,
пространственным индексом и финальным перебором небольшого множества сайтов.

## Соответствие серверному архиву

Штатный `submission/make_zips.sh` объединяет заголовки в `dist/main.cpp` и создаёт
`dist/case03_cpp.zip`. Внутри ZIP находятся только `main.cpp` и `Makefile`.
Оба файла побайтово совпадают с ранее проверенным `case03_cpp_server_v4_O3.zip`.
Метаданные ZIP могут отличаться, поэтому сравниваются распакованные файлы.

- SHA256 `main.cpp`: `5b3914fa9791cb879f3232fb2876a915de83b848ad4b353b0dbf25b574998c25`.
- SHA256 исходного архива: `b4e9ace4ed6cffe53b932bb1d10f7ecdfdcc4170458afaf05e16b3068ebae953`.
- `make build`: `g++ -O3 -std=c++17 -o solution main.cpp`.
- `make run`: `./solution`.
- По умолчанию 280 секунд, до 16 доступных потоков; `TL` и `NT` позволяют изменить параметры.
- Только `instance.json` → `solution.json`. Внешние библиотеки и MILP не требуются.

Исследовательские файлы в `experiments/` не нужны для сборки. Исходный архив сохранён
как исторический артефакт; каноническими исходниками для этой ветки являются `solver/`
и `submission/cpp/Makefile`.

## Состав

| Компонент | Реализация |
|---|---|
| Генетический поиск наборов офисов | `solver/evolution_warm.h` |
| Назначение многопрофильных работников | `solver/sol.h` |
| Переиспользование памяти | `solver/fast.h`, `engine.h`, `geom.h`, `sol.h` |
| Точные предикаты binary64 | `solver/geom.h`, `sol.h`, `check.h` |
| Индекс всех сайтов и офисов | `solver/spatial_geometry.h` |
| Финальный монотонный добор | `solver/finish.h` |
| B&B по 24 сайтам при N≤1500 | `solver/boundary.h`, `boundary_tail.h` |

В точном предикате используется GNU `unsigned __int128`. Обычные проверки выполняются
сначала быстрым фильтром, неоднозначные — точной арифметикой. Индекс учитывает и закрытые
офисы, и необслуживаемые сайты. B&B запускается в оставшееся время после основного поиска;
`BOUNDARY=0` отключает его. Остальные переключатели описаны в `SOLVER.md`.
