# Серверная сборка v6

Архив: [case03_cpp_server_v6_O3.zip](artifacts/case03_cpp_server_v6_O3.zip).

Проверенный исследовательский гибрид оформлен как v6 для серверной проверки. Реализация и ZIP побайтово совпадают с frozen-кандидатом:
переименован архив, новых настроек или изменений после holdout нет.

Включены пакетное обновление оболочек, исправление сигнатуры закрытия офиса,
финальная геометрическая доработка и совместная DP по числу сайтов и нагрузке.
Порядок новых финальных стадий: geometry → joint count/load → исходный boundary.
Параметры включены по умолчанию, переменные окружения для их включения не нужны.
Лимит по умолчанию 280 секунд; потоки определяются по доступным CPU, как в v4.
Все сравнения качества выполнены при NT=2.

В корне ZIP находятся только `main.cpp` и `Makefile`.
`make build` использует `g++ -O3 -std=c++17 -pthread`, `make run` запускает `./solution`.
Без аргументов решатель читает `instance.json` и пишет `solution.json`.
SCIP/HiGHS применялись в исследовании; в посылке они не требуются.

Это экспериментальная версия: на независимом holdout среднее изменение против v4
составило +0,1332% при TL60 и −0,1765% при TL280; худшая пара TL280 −2,0007%.
Устойчивое превосходство не установлено. Полные данные —
[отчёт исследования](../v4_deep_parallel/integration/REPORT.md).

Воспроизводимая упаковка: `python3 experiments/server_v6/build.py`.
Проверка новой копии архива: `.venv/bin/python experiments/server_v6/check.py`.
Проверка сохраняет логи в новый каталог и не перезаписывает прошлый запуск.
Она компилирует ZIP, сравнивает runtime с исследованным бинарником после удаления
ELF metadata и проверяет 28 синтетических случаев через официальный валидатор
с конкурсными именами файлов и без аргументов запуска.
