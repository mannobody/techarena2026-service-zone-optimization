# Возмущения точной серверной v4

Исследовательский раунд 19 октября 2026. Baseline, предыдущие эксперименты
и ZIP сохранены; результаты и кандидаты хранятся отдельно.

- `baseline/`: побайтовая копия серверной v4, O3 binary и проверенное происхождение
  из ZIP. Source SHA256 `5b3914fa9791cb879f3232fb2876a915de83b848ad4b353b0dbf25b574998c25`.
- `geometry_lab/`: малые обмены/циклы, замена опорных точек, геометрические oracle,
  отрицательные результаты и сравнения с расходующим бюджет native LNS/boundary.
- `escape_lab/`: ограниченные эпизоды при застое, late acceptance, tabu, удержание
  лучшего, измерение действительного восстановления, исследование geometry kick.
- `shared/`: новые development inputs, exact-v4 checkpoints, runner, анализ,
  проверки происхождения и непересечения CPU. Checkpoint reader — строго offline.
- `integration/`: полные абляции, конфигурации и разбор выигрышей/проигрышей,
  независимая проверка после freeze. Итоговое решение — в REPORT.md после завершения.

Первичный протокол и его поправки хранятся отдельно: `PROTOCOL.md`,
`PROTOCOL.json`, `PROTOCOL_ADDENDUM.md`. Распределение CPU задано явно; не запускайте
параллельно старые specs, использующие одни ядра. Пара содержит два физических
ядра, NT=2. У каждой записи сохранены stderr, wall/RSS, status, официальный
валидатор, source/binary/input hashes. Несколько seed одного входа не увеличивают
число независимых задач. Старые751000+ inputs не считаются новым holdout.

## Воспроизведение

Команды выполняются из корня репозитория. Существующие журналы не перезаписывать:
скопировать нужный JSON spec, изменить только `destination` на новый каталог и
при необходимости выбрать свободные `cpu_pairs` (сохранить одинаковые CPU внутри
каждого case/seed блока). Затем:

```sh
.venv/bin/python experiments/v4_perturbation/shared/run_blocks.py NEW_SPEC.json
.venv/bin/python experiments/v4_perturbation/shared/analyze.py NEW_LOG_DIR NEW_SUMMARY.json
.venv/bin/python experiments/v4_perturbation/shared/audit.py
```

Точная сборка базы (новый выходной путь, существующий binary не затирать):

```sh
taskset -c 20,21 g++ -O3 -std=c++17 -pthread \
  experiments/v4_perturbation/baseline/frozen_v4.cpp -o /tmp/szo_v4_rebuilt
```

Полные исходники и команды сборок каждого исследовательского binary указаны
в его BUILD/FREEZE manifest. Сначала сравнить hashes, затем запускать spec.
Не использовать текущий `solver/` как замену exact v4. `shared/setup.py` откажется
перезаписывать уже созданный раунд. Все новые входы и решения уже сохранены.

Ничего не перемещено и не удалено, карантин пока не понадобился. Начальный
`PREEXISTING_HASHES.json` позволяет проверить сохранность всех существовавших
файлов проекта (кроме git internals и venv). Полные исходники генератора
и допустимые параметры записаны вместе с входами.
