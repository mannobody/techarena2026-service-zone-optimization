# Correctness argument and isolated tests

Batching modifies no geometric predicate. During deferred removal and journal rollback, only assignments, membership vectors, sizes, task loads and skill demands are changed. Rebuild requests mark the affected office dirty. No coverage-dependent feasibility query is permitted before end_defer flushes every dirty office. Engine::doClose preserves the enclosing deferred state, clears that office's old coverage and cancels its dirty flag; the office is empty afterward. Undo contains no feasibility query, so it can rebuild once after all inverse operations. The flush regenerates precisely hull(office + current members), then enumerates all input points using the frozen exact predicate and grid. Thus final cov/incov are the same as rebuilding after every mutation. Original member ordering and journal semantics are retained. The arithmetic order of profit increments is unchanged.

The differential oracle generates80 small instances (duplicates, collinearity, A=0, multiple worker profiles), executes300 matching six-site removal/reassignment transactions under batchoff/on per instance, and fully recomputes derived state after changes and rollback. Result:24000 differential transactions;96000 state checks passed. It checks assignment, active offices, size, task load, skill needs/counts, coverage, per-office incidence, sorted covered-point lists, signature and no pending deferred state. It does not assert that arbitrary random final transactions satisfy count/worker balance; those are held identical and production accepts only after its usual feasibility check.

Worker memoization caches only successful complete worker assignments. The key contains the entire office×skill Boolean requirement matrix and each office's active/nonempty bit. Counts of equal-skill tasks do not affect feasibility because workers have no task capacity. A cache hit is exact for a single fixed instance; unordered_map still compares the complete string, so hash collisions cannot accept invalid certificates. A bounded DFS failure is not a proof of infeasibility and is never cached. The cache is thread-local and cleared when size4096 is reached. Production handles exactly one instance per process; testing multiple instances in one process would require cache isolation, so the oracle uses one process per instance.

ALNS and archive changes alter which already supported transitions/states are explored, leaving Engine validation and offer verification intact. Persistent states are saved only after count feasibility and worker feasibility, and all geometry updates use the same Engine. The niche archive contains only states already admitted by the frozen offer/try_elite validation. Crossover removes conflicting assigned sites/office anchors from incoming elite hulls and re-adds through Engine::doAdd; incoming partial geometry is checked anew. The crossover is disabled when GEO_EXACT=0; no legacy approximation is introduced.

Full solver validation, runtime/return-code checks, and fixed-work timing are separate experiments. Passing this oracle or observing a faster kernel does not establish better objective quality under a wall-clock limit.
